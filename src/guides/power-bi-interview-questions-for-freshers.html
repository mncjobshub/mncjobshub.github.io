Power BI interviews for fresher analyst and developer roles usually cover data cleaning, data modelling and DAX basics. Here are the questions that come up most, with short answers you can adapt in your own words.

1. What is Power BI and what are its main components?

Power BI is a business intelligence tool for connecting to data, modelling it and building interactive reports. The main components are Power BI Desktop (where you build reports), the Power BI Service (the online service for publishing and sharing) and the mobile apps for viewing reports.

2. What is the difference between Power Query and DAX?

Power Query is used to connect to and clean or reshape data before it is loaded, for example removing duplicates, changing data types or merging tables. DAX (Data Analysis Expressions) is a formula language used after loading to create measures and calculated columns for analysis.

3. What is the difference between a calculated column and a measure?

  • A calculated column is computed row by row when data is loaded and is stored in the model.
  • A measure is computed at query time, based on the filters and visuals in use, and is not stored per row.

Use measures for aggregations such as totals and ratios, and calculated columns when you need a value for each row to filter or group by.

4. Explain row context and filter context

Row context means "the current row" and is created in calculated columns and iterator functions such as SUMX. Filter context is the set of filters applied by slicers, visuals, rows and columns of a table, and by functions like CALCULATE.

5. What does CALCULATE do?

CALCULATE evaluates an expression after modifying the filter context. It is the most important DAX function.

Total Sales = SUM(Sales[Amount])

Sales LY =
CALCULATE([Total Sales], SAMEPERIODLASTYEAR('Date'[Date]))

Sales Growth % =
DIVIDE([Total Sales] - [Sales LY], [Sales LY])

Using DIVIDE instead of the / operator avoids errors when the denominator is zero.

6. What is a star schema and why is it recommended?

A star schema has one central fact table with numeric events such as sales, connected to dimension tables such as date, product and customer. It is easy to understand, performs well and gives predictable filtering, so it is the recommended design for Power BI models.

7. What is the difference between Import mode and DirectQuery?

  • Import loads a copy of the data into Power BI. It is fast and supports the full range of features, but the data must be refreshed.
  • DirectQuery keeps the data in the source and sends queries to it when you use the report. Data is more current, but performance depends on the source and some features are limited.

8. What types of relationships exist in Power BI?

One-to-many is the most common, followed by one-to-one and many-to-many. Filters usually flow from the "one" side to the "many" side. Cross-filter direction can be single or both; use "both" carefully because it can produce unexpected results.

9. What is row-level security (RLS)?

RLS restricts which rows of data a user can see. You define roles with DAX filter rules in Power BI Desktop, for example a manager seeing only their region, and then assign users to these roles in the Power BI Service.

10. How do you improve report performance?

  • Remove columns and rows you do not need.
  • Use a star schema and avoid unnecessary many-to-many relationships.
  • Prefer measures over heavy calculated columns.
  • Limit the number of visuals on a page.

How to prepare

Build one end-to-end dashboard from a public dataset: clean it in Power Query, model it as a star schema, write a few DAX measures and design clear pages. In the interview, walk through your choices and the insight the dashboard gives. Also revise SQL, because most Power BI roles expect it; see our SQL interview guide.
